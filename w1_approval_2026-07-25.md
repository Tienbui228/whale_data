## API FACTS (sự thật đo được, không phải giả định)

- `/futures/data/*` (OI, topLSR, topLSA, globalLSA, takerRatio): cửa sổ hợp lệ
  = 29d exclusive. `startTime ≥ now − 30d` → -1130 "parameter 'startTime' is invalid".
  `startTime = now − 29d` → OK. Probe raw 25/07.
- `/futures/data/*` khi range > limit → trả về `limit` items **MỚI NHẤT** (tail
  truncation), thứ tự ascending trong response. Bằng chứng: W1c store min_ts = now−500h
  = now−(limit×HOUR_MS) với mọi canary; nếu API cắt từ đầu, min_ts đã là now−29d.
  Probe A (25/07): startTime=June27, endTime=July4 → 170 rows June27→July4 ascending
  (window < limit → không bị cắt). Hệ quả: startTime-cursor (kể cả +HOUR_MS) nhận
  cùng ĐUÔI MỚI mỗi trang → trùng lặp. Fix duy nhất: **endTime cursor (walk backward)**.
- startTime alignment cho period-based endpoints: API trả `[]` khi startTime KHÔNG nằm
  đúng trên mốc period (hour boundary). Áp dụng cho CẢ endTime cursor: startTime trong
  mọi page là `start_ms` gốc (now−29d = không căn chỉnh). Fix: `aligned_start =
  (start_ms // HOUR_MS) * HOUR_MS` trước khi build params. Confirmed W1d re-run (25/07):
  căn chỉnh startTime 15:15→15:00 xóa sạch 54 FAIL cells trong 300s / 59 symbols.
  Tên sự kiện log cũ "Bước +1ms" là wrong frame — issue là alignment, không phải step.
- Luật kiểm tra số thiếu: mọi lời giải thích phải kèm bằng chứng độc lập kiểm được —
  đối chiếu twelve_cases/calib trước tiên vì hệ này có ground truth.
- Gate (c) tiêu chí pass thật: `min(as_of_ts) ≤ mép 29d` (cũ hơn = tốt hơn, không phải
  ngược lại). Script gate cũ `min_ts >= cutoff` sai chiều — đã sửa trong W1d.

- `/futures/data/*` pool rate limit: pool này RIÊNG với general fapi pool. Empirical:
  525 symbols × 5 metrics × 2 pages ≈ 5250 calls/run gây saturate khi share 2000/min
  budget. Fix: `RateLimiter(500/min)` riêng cho mọi path bắt đầu `/futures/data/`.
- Pool rate limiter budget 500/min là conservative starting point — tune bằng đo thực.
- Store birthday ≠ listing date: `Apr25 08:00 UTC` trong kho = ngày collector chạy lần
  đầu, KHÔNG phải listing date Binance. Listing date thật (klines startTime=0 limit=1):
    - HUMAUSDT: 2025-05-26 13:00 UTC
    - ATUSDT  : 2025-10-29 11:00 UTC
    - ACHUSDT : 2023-02-22 14:00 UTC
  Verifier: `GET /fapi/v1/klines?symbol=X&interval=1h&startTime=0&limit=1`
  Note: `/futures/data/*` REJECT startTime=0 (-1130); klines chấp nhận.
- ALLUSDT top_pos_1h + top_acct_1h: 94.4% sau re-run = genuine API hole (không phải
  collection bug). min_ts=June26 15:00 ≤ mép+12h → PASS gate. Binance thiếu data
  liên tục cho ALLUSDT topLSR trong một số giờ thuộc cửa sổ 29d.
- Nhãn sai trong report đầu (trước re-run): "listing date" cho HUMA/AT → phải là
  "store history start"; "liquidity/availability cutoff" cho ETH/DOGE/TRX Group 2b →

- Tripwire paginate_truncation_gap: bug xác nhận — exception từ client.get() trong
  vòng lặp pager thoát khỏi for loop TRƯỚC khi post-condition chạy. Fix: bắt exception
  ngay trong loop body (try/except around client.get()), log paginate_fetch_error, break.
  Post-condition sau for/else block chạy bình thường. Guard KHÔNG cần try/finally.
